## 4. HTML Demo 的范围与页面规划

### 4.1 选型定位

采用**一个可直接离线打开的交互式 CLI 导览页**。核心是命令、计划、步骤结果和后续处理，不复刻管理后台，不建 Web 服务，不在浏览器执行 Java、不访问真实 API。页面行为只修改浏览器内的演示视图，不读写 Java 的 Mock 工作副本。

优先原生 HTML/CSS/少量 JavaScript 与系统字体；不因 Demo 增加前端框架、数据库、登录或后台服务。单页脚本和必要快照内嵌，避免 file:// 下依赖 fetch 外部 JSON 或 CDN。05 写清“双击打开 index.html”的最低查看方式。

### 4.2 页面结构与必要交互

| 区域 | 展示内容 | 必要交互与边界 |
| --- | --- | --- |
| 1. 产品与范围 | 一段定位、六项 API、单条原型、两周补齐范围；醒目的“浏览器模拟 / Mock 数据”标识 | 页内导航；链接到交付物位置；不展示“已接入生产” |
| 2. 任务流程 | 查询 → 阅读详情/历史 → 计划预览 → 显式执行 → 回读；命令与场景上下文同步 | 步骤切换，不做复杂向导；允许重置浏览器演示，注明不重置 Java 工作副本 |
| 3. 内容与命令 | 待审核列表节选、明确 ID、正文/现有标签/状态、只读命令示例 | 从有限演示样本中选取；复制命令或手动选中文本；显示完整 ID，不按相似标题自动替换 |
| 4. 变更预览 | 人工给定 approve/reject 示例及理由、标签新增示例、完整 before/after 数组 | 演示默认预览；对照 `--execute --yes` 的命令区别；不提供一个假装写入真实后台的“提交审核”按钮 |
| 5. 执行结果 | JSON/可读摘要、逐步骤 write/verification、退出码、当前观测、建议下一步 | 必须切换成功、partial/4、unknown/5；展示成功后回读、部分失败只补标签、未知先核查不重试。可顺带展示 verification_failed/6，但不挤占核心开发 |
| 6. 人工/脚本/Agent | 人工给决定；脚本非交互明确授权；100 条需要额外批次/恢复能力 | 简单对比切换或说明块；Agent 区明确“未来方案”，不提供运行 100 条按钮 |

页面里的“演示执行结果”仅切换场景；复制出的 Java 命令才由用户在终端独立运行。若展示完整 MVP 的人工输入 ID 体验，应标记为“两周设计”，不能当作 48 小时原型已实现能力。

### 4.3 数据和结果来源标记

| 来源类别 | 使用方式 | 必须显示的说明 |
| --- | --- | --- |
| 原始 Mock 摘录 | 从附件选取少量内容/标签，保留正确字段；不内嵌整个后台数据集 | “原始 Mock 数据摘录”，不是联网查询 |
| Java CLI 实际运行快照 | 在核心验收和任务二完成后，提取脱敏 stdout、前后状态、JAR SHA、run-id | “Java CLI 在本地 Mock 上的实测快照”，可以追到 evidence；不是当前页面实时执行 |
| 受控故障实测快照 | 引用 FaultInjectingGateway 的真实运行；提交后丢响应须有后续独立查询证据 | “显式注入的 Mock 故障实测”，不暗示真实 API 曾发生此错误 |
| 预设产品示例 | 用于尚未实际运行的场景或两周/Agent 说明 | “预设模拟 / 待实现”，不得带“测试通过”或伪造 run-id/实测时间 |

优先用实测快照作为 Java 原型展示来源；若先做页面骨架，所有结果先标预设，证据到位再替换。HTML 不额外维护一套与 CLI 不同的输出 schema、退出码或命令名。

### 4.4 HTML 验收

- [ ] 无网络也可打开，页面无外部依赖失效/控制台错误；不启动服务即可查看。
- [ ] 页面一眼能辨认“CLI 产品导览”，能找到命令、预览和执行结果，内容/标签不是独立 CRUD 后台。
- [ ] 中文、长标题、JSON 和完整 ID 可阅读；桌面及窄窗口不遮挡关键按钮/状态。
- [ ] 查询、详情、预览、成功/部分失败/未知的场景切换可用；重置只影响浏览器视图。
- [ ] 复制命令与原型 help 一致；Clipboard 不可用时允许手动复制，不因离线环境卡死。
- [ ] 实测/受控故障/预设/未来设计均标明来源，页面不会声称已经执行审核或 100 条任务。
- [ ] 逐步结果、JSON 和退出码符合 02；没有 Token、真实账号、自动发邮件或上传入口。
- [ ] 浏览器检查留至少一份页面截图和关键交互核查记录，注明浏览器/版本；截图不能替代 Java 执行证据。

HTML 在 CLI 正常与故障结果稳定后定稿，优先完成这些交互，不投入动画、品牌图、复杂筛选或多页导航。

### 5.2 每次运行的最小证据目录

```text
evidence/task-2/<run-id>/
  environment.txt
  commands.txt
  01-list.stdout.json
  01-list.stderr.txt
  01-list.exit-code.txt
  02-detail-before.stdout.json                 后续各步沿用同样三件套
  03-history-before.stdout.json
  04-tags.stdout.json
  05-preview.stdout.json
  06-process.stdout.json
  07-detail-after.stdout.json
  08-history-after.stdout.json
  09-pending-after.stdout.json
  manifest-sha256.txt
```

图中省略了 02–09 的 stderr/exit-code 文件，实际采集每步都要有；stderr 为空也如实保留空文件。table 输出使用 `.txt`，JSON 输出必须是程序原文，不能事后把表格手工改写成“原始 JSON”。commands 按顺序记录命令与必要的非敏感配置，不导出全环境变量。

PowerShell 在每条原生 Java 命令后立即保存 LASTEXITCODE，之后才做文件保存或 ConvertFrom-Json；01 的查询、预览等不能都只记录最后一个退出码。默认预览的零写入用 Gateway 计数/工作快照 SHA 或 revision 验证，不靠一句“没有按执行”。

操作前后字段以查询 stdout 为唯一来源；06 用引用/摘录说明，不再手写一份不同的快照。若必须脱敏，保留有来源说明的提交副本与替换标记，不修改状态、计数或退出码来美化结果。实时 `.contentops` 工作目录不打包，只选必要不可变证据。
