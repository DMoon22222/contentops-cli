## 7. 复查方式、限制和停止边界

维护者可从开发仓库根执行：

```powershell
python scripts/prepare-release.py audit   # 不构建、不复制；重算并保存候选外文件清单
python scripts/render-docs.py --check
git diff --check
```

`freeze` 会拒绝覆盖已有冻结记录；`copy` 会拒绝覆盖既有候选/测试副本。不要为重跑清单而重新运行 Maven。浏览器脚本接受 `--project`、全新 `--evidence` 和已安装 `--playwright-module`，Chrome 子进程需所在工具环境允许启动。它们是开发验收工具，不是用户运行已打包 CLI 的依赖。

| 剩余事项 | 严重程度/影响 |
| --- | --- |
| 候选运行、文件和离线依赖 | 未发现新的 P0/P1 交付阻塞；通过本轮限定场景 |
| HTTP、remove/set、交互式确认、100 条执行器 | 仍未实现，沿用现有原型/两周/后续边界，不因候选验收而扩大能力声明 |
| 并发重复审核、标签丢失更新、库变更时点 | 08 的既有 P1 限制仍存在；本轮串行验收不等于修复 |
| 外置运行与查看说明、补充说明 | 待下一阶段；不是本轮候选构建失败，但最终附件仍缺件 |
| 完整 AI 会话、索引和脱敏/完整性核验 | 待独立授权的记录整理阶段；总结、Git 和日志不能替代 |
| 最终 ZIP、压缩后哈希、解压复验、最终命名 | 尚未制作，必须在用户检查候选后进行 |
| 其他浏览器、PS 5.1、真实后台、网络文件系统 | 本轮未验收，不扩大兼容性/联调承诺 |

因此可以在用户检查候选后，进入外置说明和 AI 记录整理，再进行本地 ZIP 制作与解压复验。本轮停在这里，没有自动进入上述阶段，更没有取得发送邮件或上传附件的授权。
