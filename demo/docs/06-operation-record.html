8. 异常处理与本次问题

本次没有 partial、unknown、verification_failed、超时或程序缺陷，没有恢复性写入，也没有修改 Java。已有命名规划中采用过其他 06/task-2 路径，本轮按用户指定落地到本文件和 evidence/task2，不另存重复副本。

9. 结论、复现与边界

任务二要求的“查一批 → 选一条 → 预览 → 审核及标签新增 → 新 JVM 回读”已在本次独立 Mock 副本完成，真实输出与进程码一致。审核与标签仍为两个独立 API 提交，不存在跨接口事务；此结果不证明生产权限、服务端幂等、并发安全、真实 HTTP 联调或完整业务合规。

复现业务时，在新终端或保存当前配置后设置全新的绝对状态目录，清除故障变量，再依次运行本文件中的列表、详情/历史、标签查询、预览、一次执行和回读命令；不要复用本次已审核副本。新 invocation_id、PID、日志时间和文件 SHA 会不同，应核对业务变化与步骤语义。JAR 构建/启动见 README。

本次的完整可写状态目录不作为提交证据；所需事实与哈希均已保存。scripts/record-task2.ps1 是 Git 开发工作区的逐条采集工具，不是面试官运行 CLI 的前置依赖。scripts/validate-task2.ps1 只读核查本机仍保留的本次工作副本和已存输出，不启动 CLI 或修改状态；跨环境复现请新建副本，不能盲目重放本次 execution。
