题目：内容运营后台 CLI 化

背景:公司有一套供内容运营和审核人员使用的管理后台，主要用于查询内容、处理审核、维护标签、配置分发和调整内容状态。目前这些操作主要通过网页完成。随着内部自动化工作流和 Agent 增加，公司希望将其中一部分后台能力 CLI 化，使运营人员、脚本和 Agent 可以使用同一套能力。

附件是一份从现有系统得到的接口文档。接口基本可用，但并不是为 CLI 或 Agent 调用专门设计的。

任务:

1.请设计第一阶段的 CLI 产品方案，并完成一个可以用于产品和研发评审的交付物。你需要自行决定第一阶段覆盖哪些能力，以及最终如何使用。研发资源为 1 名后端，计划在 2 周内完成第一阶段。

2.设计完成后，请查询一批待审核内容，从中选择一条完成审核和标签更新。请用文档说明如何操作。

3.如果“同一条命令将由 Agent 自动调用，并且可能一次处理 100 条内容。”，那么方案需要如何变化？请用文档说明。
